# Tests

The seed cap is 200 tests. Count expanded framework cases, imported registrations
and each executable browser journey; exclude helpers and repeated screenshots or
viewports. Keep tests through routes, Worker exports, commands and built pages,
with provider fixtures at the network edge.

Run the relevant explicit package commands after a change:

- `pnpm run test:base` for native Worker/API flows.
- `pnpm run test:data:commands` for hosted archive and erasure commands.
- `pnpm run test:installer` for local export, restore and reset.
- `pnpm run test:mail-runtime` for persisted mail delivery after restart.
- `pnpm run test:browser:readme` and `test:browser:dev-credentials` for fresh-clone
  setup, native sign-in and checkout-only development authority.
- The named `test:browser:*` commands for affected browser journeys.

Coverage includes native owner claims and mail sign-in, session revocation and
same-origin admission, no-mail operation, feedback moderation, private evidence,
accountable commitments, approved roadmap and release publication, notification
consent, integration authority, exact original files, empty-target restore,
erasure replay fences, interrupted recovery and populated upgrades.

Run tests explicitly in verification. Build, setup and deploy must not run them.
