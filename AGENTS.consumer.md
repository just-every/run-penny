# Owning this Penny source

This distribution contains editable Penny source, copied Base modules, applied
SQL, tests and custody records. It runs independently of its publisher. Keep
owner customizations and recorded intent when updating; no automatic update or
management service is required. The public source is
[just-every/run-penny](https://github.com/just-every/run-penny).

Penny implements moderated feedback, voting, explicit follows and comments,
operator evidence and decisions, separately approved roadmap wording, status
updates and immutable releases. Outcome measurement, autonomous investigation,
and broader outcome capabilities retain their own acceptance. Saved feedback
import is fixture-verified; external history grants neither identity authority nor
consent. Native owner claim/editor, requester-only host sign-in and scoped REST
keys have bounded local checks. Webhook/Slack/tracker dispatch requires an
installation-owned enforcing egress service; the current owner deployment kit
does not provision it or a custom domain. Outbound actions remain visibly
disabled until configured. Requirements and proposed journeys are not receipts.

Follow README.md and OPERATIONS.json for actual command effects and required
configuration. Run the app with `node scripts/rer.mjs install`, `setup`, `dev`:
setup starts empty, sign-in uses Base's development outbox, and the owner finishes
first-run setup at `/setup`. Owner deploy/health use `deploy.json`,
explicit account inputs and private durable owner files. The retained artifact
controller uses the separate artifact commands. Native fixture composition does
not establish hosted success.
Dependencies/builds must not receive provider credentials.

The Worker uses D1, R2, a producer Queue and Cron. Native operator admission,
requester verification, same-origin writes, moderation and public/private
projection are independent boundaries. Do not replace them with client checks,
mock application services, hidden failure or a fallback transport. Unknown
configuration fails visibly. Keep files small and remove retired paths.

Read CONTRACT.md, BASELINE.md, ACCEPTANCE.md, HANDOVER.md and the actual tests
before editing. Deliberate owner changes are legitimate; document changed
requirements and consequences with meaningful verification. Preserve applied
migration bytes and append tested forward migrations. Keep expanded schema on
source rollback; isolate recovery, revoke restored credentials and reconcile
uncertain effects before switching traffic. Never replay held notification
history or automatically resend an ambiguous SendGrid result.

Use the documented pnpm run export/import commands with private session files
and the latest separate erasure journal. The bounded archive includes classified
product records and original R2 bytes, excludes installation authority and
provider secrets, and preserves destination Base authority. It is not an
identity backup or universal data acceptance.

Run focused checks, the full gate and real affected browser journeys before
adoption. Passing local/provider-fixture tests do not establish hosted mail,
Cron, registry admission or public release. Prepare updates separately from the
live installation; retain exact source custody, customizations and recovery
receipts, and resolve conflicts deliberately. This guide ships at its own path;
AGENTS.md remains the source-maintenance instructions.

Integration tokens, provider keys, destinations and signing material stay in
installation custody and are excluded from portable archives. Product events,
tracker links/state and commands are classified; restore holds pending effects.
Re-enter secrets and reconcile uncertain outcomes before enabling transport.
General tracker sync and automatic public-status/commitment remain excluded.
