# Authoring Penny

Penny connects attributed customer evidence to an explicit decision, separately
approved public roadmap wording and immutable release communication. Preserve
original evidence and commitment/publication snapshots; editing an internal
record must never silently change public wording.

The production Worker and Hono admission live in src/core/worker; features live
in src/core/features and document/UI composition in src/core/app and routes.
Use the existing small validation, transaction and publication services. Product
bindings and policy belong in src/ext and feature adapters; copied Base bytes
stay unchanged while exact custody is claimed. Native operator authentication
and requester authority are separate; every private function checks admission.

Read the contract and current acceptance boundary before adding a capability.
Add a small clause-named test only for a new or changed user/business flow,
through its public command, route, transport or built page. One-off fixes use
before/after evidence. Avoid fixed metadata, wording and threshold assertions.
Keep assertions for required behavior; replace or remove obsolete tests
and record the reason and replacement. Append SQL, prove a populated
previous-head upgrade/repeat, and extend explicit archive classification so new
personal records participate in export and erasure. Installation/provider
credentials remain non-portable. Never use a client-only permission check,
production mock, hidden old path or fallback transport.

Use Node 22.20.0 and pnpm 10.12.4. Install frozen dependencies, run changed-area
flow checks while iterating, then stage intentional inputs and run source:lock,
source:check and verify:base-source. CI runs the full verification wall. Keep retained snapshots and
modes/hashes with the source; [source provenance](SOURCE-PROVENANCE.md)
distinguishes offline byte checks from private upstream comparison. Inspect
affected desktop/mobile browser states,
privacy, genuine 404s, Origin/session denial, accessibility, layout and teardown.
Local fixtures prove their bounded behavior; they do not prove a live inbox,
Cron, admission registry or public launch.

README.md documents the browser/terminal installation and private data commands.
Product hooks live in scripts/installer; Base owns their command capture, settings
lock and process custody. Ordinary and predecessor builds share protected real
commands. Keep product name/accent/description in src/branding.json. Owner-account
setup uses deploy.json and private durable owner files; the artifact controller
remains separate. Import and integration additions must first earn their named
native receipts.
Keep Unreleased changes, RELEASE migration/reconfiguration instructions and
ACCEPTANCE/HANDOVER truthful. Preserve 0.0.0 and existing tags until a separately
authorized release; public preparation uses the maintained Base tool and a
reviewed parentless tree, preserving private ancestry.

Browser journeys require PENNY_BROWSER_EXECUTABLE to name an installed headless
browser executable. Set that machine-local path outside committed source. The
journeys use software rendering and fail visibly if the required input is absent.
